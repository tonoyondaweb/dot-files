# flow on T3

The Lead reads this once per session. It maps flow's delegation terms to T3 primitives, modeled on pstack's harness docs.

## Spawning

| flow term | T3 |
| --- | --- |
| Spawn a role | `delegate_task` with `target.providerInstanceId` and `target.model` from the registry (`.flow/roles.yaml` in the project, else `<flow>/roles.yaml`), and `title: "<role>: <unit>"`. A role set to `inherit-parent` omits `target`. |
| Effort | `target.options`: `effort` on claudeAgent, `variant` on opencode. Antigravity has no option; effort is baked into the slug (`-low`, `-medium`, `-high`). |
| Background | `mode: "async"`. Completion wakes the Lead. Never poll. Use `task_status` only when the result is needed mid-turn. |
| Isolated checkout | `isolation: "worktree"` on the `delegate_task`, for every code-writing child. Commit first; uncommitted edits are not copied. Never `t3_thread_launch` or `create_threads` for a child: those make top-level threads. |
| Read-only (Explorer, reviewers, a researcher with no findings file) | `isolation: "shared"` plus FORBIDDEN in the brief, then `git status --porcelain` must be empty after. T3 has no read-only switch; `runtimeMode` is not one. |
| T3 role tag | `role`: worker→`implementation`, explorer/researcher→`research`, verifier/adversary/panel→`review`. |
| Retry, fix round, follow-up | A fresh `delegate_task` with consolidated scope: original brief, every later directive, the prior report and branch. New `clientRequestId` per round, stable across retries of that round. Never `t3_thread_send` to a child. |
| Child asks a question | `hasPendingQuestion` → `t3_pending_request_read` / `_respond` with `threadId=childThreadId`, or escalate to the user. |
| Stop | `task_cancel`. |
| Ask the user | `AskUserQuestion`. |

## Model choice

Start from the role's entry. Raise effort one step for the hardest or subtlest work, lower it for routine work. Keep the family. A panel stays diverse only if each entry keeps its family. Effort ladder: `max > xhigh > high > medium > low`. If the model lacks that rung, take the nearest rung at or below it (DeepSeek and GLM have only `low`, `high`, `max`). If `delegate_task` rejects a target, use the role's entry unchanged and say so. If it rejects that, use the closest valid model of the same family from `orchestrator_capabilities` and flag `roles.yaml` for an update.

Panels (`review` in the Review playbook, `arena-runners` in the Prototype playbook): spawn every entry in one turn. A cross-judge comes from `cross-judge pool`, from a different family than the Lead's when possible. Agreement across families is high-signal.

## Ownership

The Lead owns every child's output. Read the diff and write your own summary; never pass a child's report through.

## pstack and p3-stack features and their flow equivalent

| pstack / p3-stack | flow |
| --- | --- |
| `pstack-models.mdc`, `p3-models.md` | `roles.yaml`, written by `setup-flow`; `.flow/roles.yaml` per project |
| `poteto-mode`, `p3-mode` | `skills/flow/SKILL.md` (`/flow`) |
| `poteto-agent`, `p3-agent` | `agents/flow-agent.md` |
| Worker worktrees via `t3_thread_launch` | `delegate_task` with `isolation: "worktree"` |
| Bugbot | Open Code Review (`ocr`) in delegation mode |
| `/loop`, poll loops | `watch_pull_request`; `schedule_task` for other cadences |
| `agent-transcripts` mining | `t3_thread_search`, `t3_thread_read` |
| `control-ui`, `control-cli` | `preview_*`, `device_*` |
| `show-me-your-work` decision trail | the wayfinder map and its tickets |
| Cloud agents | none. Skip and say so. |

## T3 tool quick reference

- Delegation: `orchestrator_capabilities`, `delegate_task`, `task_status`, `task_cancel`
- Child questions: `t3_pending_request_list`, `t3_pending_request_read`, `t3_pending_request_respond`
- Pull requests: `link_pull_request`, `list_thread_pull_requests`, `watch_pull_request`, `unwatch_pull_request`
- History: `t3_thread_search`, `t3_thread_read`
- Proof: `preview_open`, `preview_navigate`, `preview_snapshot`, `preview_click`, `preview_type`, `preview_wait_for`, `preview_recording_start`, `preview_recording_stop`; `device_list`, `device_open`, `device_screenshot`, `device_close`
- Visuals: `html_preview`, `html_render`
- Schedules: `schedule_task`, `list_scheduled_tasks`, `run_scheduled_task_now`
- Not for children: `t3_thread_launch`, `create_threads` (top-level threads, only when the user asks for one)
